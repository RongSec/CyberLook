## 0. 这份文档想解决什么

大多数"资产扫描系统"交付的是**一次扫描的结果**：导出一张表，人看一眼，然后就过期了。
内网真正难的不是扫一遍，而是回答三个持续存在的问题：

| 问题 | 难在哪 | 未见的答案 |
|---|---|---|
| **这台机器还在吗？** | 一次丢包、一次防火墙抖动，都会被误判为"下线" | 缺席只记账，连续 3 轮才转「睡眠」；每轮命中即回「活跃」。**不删记录** |
| **这台机器上跑的东西变了吗？** | 端口没变、服务换了；页面还是那个 URL、内容改版了 | 页面 SimHash + 标题/响应码/长度四路比对，旧值留档 |
| **这个结论凭什么？** | 报告里写"开放 3306"，三个月后没人能复现 | 每一轮扫描的原始行落本地审计库，单元级可回溯 |

所以这个平台的核心不是"扫描器"，而是**资产的账本**：
扫描是记账的输入，资产表是多轮扫描叠加后的最小共识，处置与合规是账本的用途。
下面按一台主机走完一遍的路径来讲。

## 1. 一台主机的全生命周期

![资产生命周期](docs/images/diagram-lifecycle.svg)

十个环节，每一步只做一件事，且都能单独重跑：

| # | 环节 | 输入 | 输出 | 失败/边界怎么处理 |
|---|---|---|---|---|
| 1 | **IP 规划** | 网段、台账、手工 IP | 去重、去免扫描后的目标 IP 集合 | 免扫描支持 `198.18.5.10-20`、`198.18.5.0/24`、`*.*.*.1`；内置一条"每个网段的 .1" |
| 2 | **存活探测** | 目标 IP 集合 | 存活 IP（极少时也照实记账） | ICMP 批量 + TCP 16 端口兜底；抽 2% 判死主机低速复核，发现漏判就降并发重扫 |
| 3 | **单元化排队** | 存活 IP 列表 | 每个 IP 一条 `task_units` | 1 IP = 1 单元，租约 60s，节点掉线自动回收重派，最多 3 次 |
| 4 | **端口扫描** | 单元 + 端口集 | 开放端口 + 证据 | 单机令牌桶 300 pps、全局限速；被中间设备代答的端口剔除；全端口应答设备收敛 |
| 5 | **服务识别** | 开放端口 | 产品/版本/标题/响应码/页面指纹 | 四级递进，拿不到就降级为裸 `tcp`，绝不编产品名 |
| 6 | **归一入库** | 识别结果 | `assets` + `services` 增量更新 | 幂等 upsert；首见归本轮任务，之后只更新 `last_task_id` |
| 7 | **变更感知** | 本轮 vs 上轮 | `prev_*` 旧值、`content_changed` | 与**确认时的基准**比，不是与台账标题比 |
| 8 | **处置与归属** | 待处置队列 | 系统名/责任人/部门 | 新出现、新变更、台账导入三类入口；确认即重建基准 |
| 9 | **合规与证据** | 服务记录 | 疑似/违规标记、页面快照 | 扫描期只做数据比对标记，实连确认由人一键触发 |
| 10 | **缺席与结算** | 本轮未命中的服务 | `miss_count`，连续 3 轮转 `sleeping` | 抗抖动：一次没扫到不等于服务消失；只改状态不删行，避免重扫又变「新发现」 |

配套两条旁路（不影响主链路，可独立关闭）：

- **审计库**：节点本地 SQLite（WAL），每个单元一轮一个 Project，保留 7 天 / 512MB；
- **任务日志 + 通知**：存活清单、判定与复核结论、参数行、识别结果逐条落库，并可按事件推送到企业微信/钉钉/飞书/邮件。

## 2. 单条服务的状态演进

资产的"动态"落到最后，是一条 `ip:port` 记录在几个状态之间移动：

![服务状态演进](docs/images/diagram-state.svg)

三条规则决定了它不会乱跳：

1. **命中即刷新**：任一轮扫到该端口 → `last_seen` 刷新、`miss_count` 归零。
   表达现状用"最近一次看见"，而不是"曾经看见过"。
2. **缺席不删记录**：未命中只累加 `miss_count`，连续 3 轮转 `sleeping`，重新扫到立刻回 `active`。
   一次超时、一次防火墙限速、一次节点被限流，都不该让资产消失；而删了行，下轮重扫又会变成「新发现」。
   计数单位是**这个 IP 被扫描的轮次**：领取失败/被隔离的单元不算一轮，同一任务重复收尾不双计。
3. **新旧并存**：变更时旧值写入 `prev_title` / `prev_fingerprint` / `prev_status_code` / `prev_content_length`，
   当前值照常前进。处置页面展示的是"旧 → 新"，不是覆盖后的既成事实。

> 主机级与端口级是两个粒度：`assets.status` 只有 `pending` / `confirmed`；
> 增删与变更发生在 `services`。同一台已确认的主机新冒出一个 Web 服务，会被拉回待处置。

## 3. 数据模型：扫描是过程，资产是结果

![数据模型](docs/images/diagram-model.svg)

关键字段与其职责：

| 表 | 关键字段 | 说明 |
|---|---|---|
| `scan_tasks` | `status` / `total_ips` / `alive_count` / `probe_offset` / `timeout`(ms) | 一次任务；可删除、可重跑，**不承载资产事实** |
| `task_units` | `status` / `lease_expire` / `attempts` / `probes_done` / `probes_total` | 1 IP = 1 单元，进度分母 = Σ`probes_total` |
| `services` | `first_seen` / `last_seen` / `miss_count` / `page_simhash` / `prev_*` | 端口级事实，`(ip, port)` 唯一 |
| `assets` | `status` / `source` / `system_name` / `owner` / `confirmed_simhash` / `content_changed` | 主机级事实，一台一条 |
| `compliance_*` | 规则与结果 | 可直连数据库等违规的判定与确认记录 |
| `page_snapshots` | 页面截图与哈希 | Web 资产的可视证据 |

`services.task_id` 记"首次发现归属哪一轮"，`last_task_id` 记"最近一次看到"。
两个字段分开，任务被删也不会让资产失去出处。

## 4. 执行面：调度在中心，判定在节点，证据在本地

![执行面](docs/images/diagram-deploy.svg)

- **中心不碰数据包**：目标展开、单元化、租约发放、进度与 ETA、入库与变更判定全在 server 侧；
  因此 server 可以放在管理网，只有节点需要能到达目标网段。
- **节点不存台账**：`scope-agent` 是单二进制（Linux/Windows），进程内直调引擎，不起外部进程；
  本地只保留审计库。
- **单机 CLI 与平台同一份代码**：`portscan` + `svcid` 两个包，`cyberlook-scan` 直接编译可用；
  参数行/进度行/完成行由同一套格式化函数生成 —— 同一个目标在两边给出不同结论，就是 bug。

### 4.1 单元调度

`claim → 扫描 → 流式上报 → finish → 释放`。结果按"每 ≤200 条或 ≤300ms"批量上报；
掉线后租约 60s 到期，单元回到 `pending`，重试 3 次仍失败才标 `failed` —— 不静默丢 IP。

### 4.2 配速与假阴性

吞吐的唯一决定因素是"在途探针数"，但它有三堵墙：fd、CPU、内存。
节点自己闭环调节（每 10s 看 EMFILE 计数、**整机** CPU、本窗口实际探针数），
在 `[base/4, base]` 内移动；人工下发的 `limit/pause` 优先，不被自动逻辑推翻。

单目标另设 300 pps 的令牌桶：常见防火墙对**同一目的 IP** 的 SYN 限速在 100~1000 pps，
超了就是静默丢包 → 开着的端口被判成关闭（假阴性）。300 pps 下扫完一台 65535 端口约 3.5 分钟。

存活探测同样有复核机制：抽 2% 判死主机以 1/8 速率重探，只要发现漏判就整体降并发重扫。

### 4.3 两类"看起来开放"的假阳性

| 现象 | 判定方式 | 处理 |
|---|---|---|
| 80/443 对**任意地址**都回 SYN-ACK（中间设备代答） | 对 RFC5737 保留地址 `192.0.2.1` / `198.51.100.1` 探同一批端口 | 该端口从判活集合中剔除，任务日志写明"被中间设备代答" |
| 单台主机"开放"上万个端口（SYN 代理 / 全端口转发 / 蜜罐） | 单 IP 开放数超过 256（端口集 ≥1024 时生效） | 判定为全端口应答设备，停止该主机的识别与入库，保留前 256 个并记日志 |

后者来自实测：一台这样的设备曾产出 12,905 条伪服务记录（占整库 98%），
把 32 并发的识别池打满、CPU 打到 97%，同节点另外 6 个单元被拖到重试耗尽。

### 4.4 CPU 预算：给平台留一点余量

平台中心和扫描节点常混部在同一台机器上（web、PostgreSQL、AI 识别、chromium 渲染都在 server 里）。
扫描把整机吃满时，最直接的后果是**页面打不开**——连接建得上，请求排不上队。所以两边都守一条预算线：

```
预留核数 = 4 核留 1、8 核及以上留 2、2 核及以下不留
整机预算 = (核数 − 预留) / 核数 × 100%，上限 92%      # 4 核 → 75%
```

- **节点**：`GOMAXPROCS` 收窄到 `核数 − 预留`；调速器改看 `/proc/stat` 的**整机**占用，
  超预算 10 点以上立刻 ×0.7 退并发（不等第二个窗口），在预算内 20 点以内维持、明显有余量才小幅加。
  在途天花板也按可用核数算（4 核 → 1050，而非 1400）。
- **服务端存活探测**：并发按核数给（`核数×220`，256~1200）；探测**分块** 2048 个 IP，
  块间看整机 CPU——超预算 20 点停 1.2s、超预算停 400ms，并把下一块并发降到 2/3（不低于基线 1/3），
  明显有余量再回补。分块只增加几个百分点的总时长，却能把这台机器上的 web 从"打不开"救回来。
- **AI 识别并发**：默认 `核数/2`（1~3 路），每条可能拉起一个 chromium 页面，单页就能吃一个核；
  每个作业前还有一道 CPU 闸门。

> 为什么必须按整机口径：v0.0.50 实测——扫描一开，识别拉起的 chromium 与指纹匹配把 4 核顶满
> （server 容器 160%~220%、`sy` 38%、softirq 15%），而旧调速只看节点**自己进程**的 CPU 时间，
> 对同机兄弟进程完全无感，于是一路加并发，直到 web 请求延迟涨到 1~4 秒。

可调环境变量：`SCAN_CPU_RESERVE_CORES`（节点）、`CPU_RESERVE_CORES`（平台）、
`ALIVE_PROBE_CONCURRENCY`、`AI_IDENT_CONCURRENCY`、`IDENT_CONCURRENCY`；设 `0` 表示"独占机器、不留余量"。

### 4.5 识别链路：先读标题，读不到再上模型

一条 HTTP 服务的识别分四层，前一层能定论就不进下一层：

```
① 抓请求响应包（最多 4 跳，协议判错自动换 scheme 重抓）
      ↓
② 解析原始 HTML 的 <title>
      ├── 标题明确、无导航后缀 ──→ 直接入库（title_source=html，0 次模型调用）
      ├── 标题可用但带「 | 首页」「- 登录」──→ 跳过判断/渲染，只让识别 agent 归整
      └── 标题缺失 / 占位 / 设备错误页 ──→ 下一层
      ↓
③ 判断 agent（按需）──→ ④ 浏览器渲染（按需）──→ ⑤ 识别 agent
```

**为什么先把 title 抠出来。** 这三个环节的代价差两个数量级：解析 title 是几十毫秒的字符串处理，
一次模型往返 1~3 秒，一次浏览器渲染 8~28 秒。页面自己写着 `数据智能平台` 的时候，
让模型重新读一遍整页 HTML 纯属浪费。实测 45 条真实服务里 10 条（22%）在 L0 就定论，
平均 61ms；这些条目在 0.0.54 里平均要 10 秒以上。

**但 title 不等于系统名**，所以 L0 只放行"明确且干净"的那一类：

| 原始 title | 判定 | 理由 |
|---|---|---|
| `数据智能平台` | 直接采纳 | 就是系统名 |
| `数据智能平台 - 登录` | 交识别 agent 归整 | 有身份，但带导航后缀 |
| `登录` / `首页` / `Login` | 不使用 | 整条都是壳 |
| `Redirection……` / `404 Not Found` | 不使用 | 结构性占位 |
| `Browser Error` | **强制渲染** | 设备静态错误页，真名由 JS 写进 title |

最后一行是实测踩出来的：`198.19.252.2:80` 的原始 HTML 写着 `Browser Error`，浏览器渲染完
才是 `H3C HDM`。这类页面判据不是"要不要相信标题"，而是"必须再渲染一次"。

**`document.title` 与原始 `<title>` 分开记。** `services.title_source` 现在有三种值：
`html`（原始标题直取）、`render`（渲染后读到的标题）、`ai`（模型判定）。置信层级一目了然，
排查"这个名字从哪来"不用再翻会话记录。

**标题缺失时才叫判断 agent。** 判断看的是"页面长什么样"（状态码、正文量、跳转链），
识别看的是"页面里写了什么"（标题、特有路径、版权行）。合在一段提示词里时，模型经常为了给名字
而忽略"这其实是错误页"，或者为了说"证据不足"而不肯输出已经看得到的产品名。拆开后各管一件事。

判断 agent 只在两种情况下被叫醒（前提是标题已经不可用）：

- 正文也少（不足 80 字）——典型壳页；
- 正文虽长但整页是外部脚本骨架（`<script src>` + 空 `<div>`）——SPA，正文由 JS 渲染。

```
kind=normal  2xx/3xx、标题明确、正文有内容      → 不渲染
kind=error   4xx/5xx、只有状态文本、默认页        → 不渲染
kind=shell   正文几乎为空、只有脚本外壳           → 渲染
kind=jump    多跳跳转、meta refresh、纯跳转页      → 渲染
kind=weak    只有厂商级线索、缺产品线            → 渲染
```

判断失败（模型不可用、输出不是 JSON）时退回本地规则（`renderWorthwhile`），不让整条链路停摆。
渲染等待也收紧了：等 `load` 事件的上限 8s → 4s，正文稳定阈值 50 字 → 10 字，静态页立即返回。

**提示词可编辑。** 「LLM 配置 → AI Agent」页有「判断」「识别」两个角色，各自的提示词可直接改、
可恢复默认；改完下一条识别立即生效（每条识别时实时读取，不缓存、不重启）。
提示词刻意写得条目化、无解释性段落——长提示词里的说明会被模型当成"可选项"，反而稀释硬规则。

**判断不是每条都跑。** 本地规则先把「明显不需要深度判定」的页面挑出去——最后一跳是 2xx、
去掉标签后的正文 ≥ 400 字，说明页面有真实内容，直接进识别；只有壳页、空壳 SPA、跳转页
才交给判断 agent。实测 68% 的服务不需要这次调用，单条省 1~3 秒。

**证据只给有用的部分。** 完整报文（16KB）里请求头 User-Agent/Accept 对判断「这是什么系统」
毫无作用，却占掉大半 token。实际送进模型的是精简版：跳转链、`Server` / `X-Powered-By` /
`Location` / `WWW-Authenticate` 几行、正文前 3KB，输入约 800 token。

**写回门槛分三档**：填空 15、指纹 15、覆盖已有有效标题 60。「填空」不覆盖任何既有信息，
最坏是填进一个技术栈名（Microsoft IIS、Kubernetes），也比列表上一片空白有信息量；
「覆盖」则要求模型足够确定，避免把正确旧值换成半对的新值。

**队列可见。** `GET /api/services/ai-stats` 返回并发数、内存队列长度、库里待识别（仅 HTTP）、
最近 5 分钟吞吐、四阶段平均耗时（抓包/研判/渲染/识别）、渲染采用与跳过数、ETA；
进度显示在**扫描页**工具栏：`服务识别：待识别 N 条 · X 条/分 · 约 Y`。

**单条硬上限 90 秒，到点取消而不是干等。** 识别 worker 的看门狗除了销毁浏览器实例，
还会 `cancel()` 整条链路的 `ctx`：渲染里的 CDP 调用、LLM 调用都挂在同一个 ctx 上，
取消后立即返回，worker 当场归还。早期只杀浏览器不取消，协程会傻等 HTTP 客户端自己的长超时，
实测有一条拖到 125 秒，等于白占一个 worker 半分钟。

### 4.6 入库口径：非 HTTP 不排识别，占位标题照原样保留

**占位标题照原样入库。** `502 Bad Gateway`、`Not Found`、`Redirection……` 这类状态文本
就是原页面真实写的内容，列表上直接显示它比显示空白更有信息量。它们同时是"需要 AI 复核"的信号，
进识别队列后由判断 agent 定类型、识别 agent 拿到名字自然覆盖；拿不到名字就保留原文，
不会出现"空标题"。

**非 HTTP 不打 `ai_need`。** 引擎对 TCP/MSRPC/SMB/RDP 也标"需识别"，但识别链路只处理 web，
这些行进队列就被直接标 `checked`、什么也不做——旧口径下积压里 6,674/7,461 都是这种假积压。
现在入库只对 HTTP(S) 打标记。

**识别不再需要手动触发。** 「应用服务」页的「AI 批量识别」按钮已移除；识别队列由
`services.ai_need` 驱动、后台每 15 秒补给，进度显示在扫描页。
队列落库语义：内存队列只是加速通道，重启后从 `ai_need` 重新补给，不丢待办。

## 5. 服务识别工作流

识别是**分级递进**的，每一级失败才进下一级，全部失败就老老实实记 `tcp`：

```
① 协议探针（被动优先）    banner / 握手 → SSH、SMB、MySQL、Redis、RDP…
② Windows 主动握手        445/139/3389/135 上取真实 OS 与主机名
③ HTTP 抓页               标题、状态码、favicon 双哈希、TLS 证书 CN/O
④ 规则匹配                web 3450 条 + service 11938 条（FingerprintHub, MIT）
⑤ 主动探针                被动拿不到 banner 时按端口发对应载荷（每端口 ≤3 组）
⑥ AI 兜底                 标题为空/默认页/纯 IP 时异步走「抓完整请求响应包 → AI → 渲染 → AI 再判」
```

识别链路的"是不是这个系统"**只由模型判断**，不做产品名/标题的正则裁决
（正则永远调不完：白名单外的真系统被误杀、新默认页一出现就得补规则）。
代码里只保留两类非判断逻辑：GBK/GB2312 转码（编码问题不是判断问题）、空值与单字符拦截。

渲染这一级共用一个常驻浏览器实例：全进程 1 个 chromium，CDP 开标签页渲染，
连续 5 分钟没有任务就把实例连同 profile 一起销毁（实测单实例 VmRSS ≈ 218MB，
旧实现每次渲染 spawn 一个进程、3 并发约 600MB，且被 kill 时 `/tmp` 里会留 profile 目录）。
可调：`CHROME_IDLE_SEC`（空闲秒数）、`CHROME_MAX_TABS`（并发标签页，默认 2）、`CHROME_PROFILE_DIR`。

**喂给模型的证据必须是完整的**（v0.0.48）：请求行/请求头/响应行/响应头全量，响应体抓到 32KB
（旧实现只读 3000 字符，再截到 1500 字交给模型——SPA 首页的产品名往往在截断点之后）。
同一份完整报文同时写进会话记录，界面上折叠成「原始请求 / 响应」块，人也能逐字节复核。
另外 GBK/GB2312 页面会被整段转成 UTF-8 再判：旧逻辑遇到 `utf8.Valid=false` 直接当"二进制内容"
丢弃 body，中文标题一个字都拿不到——这是内网老系统识别不准的主因之一。

**抓页这一级有三个「看起来很正常的空页面」，都会让模型判成未知**（v0.0.49 全部修掉）：

| 现象 | 真实原因 | 处理 |
|---|---|---|
| 抓到的页面只有 `Redirection……` | 设备返回 200 + `<script>location.replace('https:'+…)</script>`，是**页面内 JS 跳转**，不是 3xx | 解析 meta refresh 与 `location.replace/href`，连同 `location: ./login` 这类相对地址一起跟（跨主机不跟） |
| https 侧完全抓不到 | Go 1.22 起默认不再提供静态 RSA 套件，老设备（超融合、老 VPN）只支持它，握手直接失败 | 单独一套 legacy TLS 配置补回 RSA 套件与 TLS1.0 |
| 渲染回来正文是空的 | 固定 sleep 600ms，Vue 登录页此时还没有一个字 | 轮询 `body.innerText` 长度，有内容且稳定即返回 |

判定上还有两条：**置信度 <80 必须继续渲染**（"深信服"是厂商级，"深信服超融合平台"才是产品级）；
**壳页标题一律不落库**（`Redirection……`、`HTTP`、`307 TEMPORARY REDIRECT`、空、默认页），
并且不覆盖已有的有效标题——错误标题一旦写进去，下轮会因为"已有标题"而不再复核，错误就被固化了。

口径上有几条刻意的克制：
- **单一弱词命中不算产品**（`score < 15` 不并入技术栈），避免一个页面报出四个产品；
- **多技术栈最多并列 3 个**，顺序即置信度；
- **占位产品名清空**：`UnKnown`、`ssl`、`tcp` 这类值不写库、不上终端；
- **"识别 N 个"只统计真的拿到产品/标题的端口**，进过识别池不算。

## 6. 指标口径

| 指标 | 口径 | 为什么这样定 |
|---|---|---|
| 进度 | `Σprobes_done / Σprobes_total` | 按 IP 计会让几万 IP 的任务长时间停在 0%，且单 IP 全端口单元的权重是 top100 的 655 倍 |
| 速率 | 短期 EWMA(10s, α=0.3) 与全程平均加权（0.65 : 0.35）；无样本时用理论初值 | 单一路径要么不跟手，要么被锯齿带跑 |
| ETA | 剩余探针 ÷ 融合速率；样本 <3 标低置信，前端显示"估算中…" | 宁可说不知道，不给会自我打脸的数字 |
| 存活探测 ETA | 只用 TCP 阶段稳态速率（>500 IP/秒的 ICMP 爆发窗口丢弃） | 旧算法把"两秒推完一半"当成速率，94k IP 显示"剩余 2 秒"，实际 7 分 36 秒 |
| 识别率 | 有指纹/标题的端口 ÷ 已处理端口 | 与"进过识别池"区分，后者会虚高 |
| 活跃 / 睡眠 | 按该 IP 被扫描的**轮次**计数，连续 3 轮未命中转睡眠 | 按任务数计会被"失败单元""重复收尾"污染，没扫过也判睡眠 |

## 8. 快速开始

```bash
git clone https://github.com/RongSec/CyberLook.git
cd CyberLook
bash init.sh                 # 生成 .env（随机数据库密码）并拉取最新 release
docker compose up -d         # server + postgres + redis + updater + 一个内置节点
```

- 控制台：`http://<server>:18888`（首次登录 `admin / admin123`，请立即改密）
- 节点加入：在「节点」页复制一键脚本；也可 `docker run`，或裸机运行
  `scope-agent -server http://<server>:18888 -name <节点名>`
- 从源码构建：`docker build --build-arg VERSION=0.0.37 -t ghcr.io/rongsec/cyberlook:0.0.37 .`
- 更新：`updater` 边车负责拉镜像与切版本，主应用不直接持有 `docker.sock`

关键目录：

```
cmd/server|agent|updater      三个入口（中心 / 节点 / 更新边车）
internal/target               目标展开与免扫描匹配（Excluder）
internal/scanner              引擎封装：流式扫描、识别池、审计库、进度解析
internal/service              调度、队列、ETA、入库、合规、通知
internal/api                  HTTP 接口
web/                          Vue3 + Naive UI 前端
migrations/                   PostgreSQL 迁移（按文件名顺序执行，幂等）
data/fingerprint/             全量指纹规则（随镜像内置）
```

## 9. 运维要点

- **迁移**：启动时按文件名顺序执行 `migrations/*.sql`，单条失败不影响后续；升级不回滚数据结构。
- **备份**：`pg_dump` 即可完整还原台账；`data/files` 存放页面快照与 JWT 密钥，需一并备份。
- **审计库**：节点本地 `config/config.db`，按保留期（默认 7 天）与容量（512MB）滚动清理，在途会话不受影响。
- **通知**：任务完成 / 新资产 / 违规 / 故障 四类事件分别开关，支持企微、钉钉、飞书、通用 Webhook、邮件。
- **多节点**：同一任务可由多节点并行消费，单元级租约保证不重复扫同一台机器。
- **混部**：平台与节点同机时，两边默认各留 1~2 核（见 4.4）；独占机器可用 `SCAN_CPU_RESERVE_CORES=0` 关掉。

## 10. 边界与已知限制

- **只做 connect 扫描**：不发半开 SYN、不做协议漏洞利用；对"回 RST 但被中间设备改写"的场景仍需人工复核。
- **全端口任务的时间成本是物理量级**：65535 端口 × 数千台，在单机 300 pps 下就是数小时到数天，配速调不动物理上限。
- **识别依赖规则库**：规则未覆盖的自研系统只能拿到标题或 TLS 证书线索，此时会标记 `title_source`。
- **不做凭据登录与内网横向**：平台止步于"资产是什么"，不做"资产能做什么"。
- **免扫描通配是四段匹配**：`*.*.*.1` 覆盖每网段 .1，不覆盖 `.254`、`.0` 之类习惯差异，需要就自己加。
